# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（无构建、无第三方依赖）。

两个页签：

- **作品看板**：新增作品，记录胎体、纹样、线条、贴线进度、阴干日期、金粉、缺陷与交付日期；工序看板、今日待阴干、缺陷、最近交付、筛选排序、JSON 导出。
- **断网合并台**：工坊断网期间用平板记录部件工序与缺陷回执，恢复后把回执包并入工坊台账。

## 断网合并台规则

- **合并键**：批次号 `batchNo` + 操作号 `opNo`；回执按此定位工序与部件。
- **序号乱到不覆盖**：工序维护独立的回执序号游标，期望序号不是回执序号时挂起为冲突，
  冲突记录同时保留 **工坊值 / 平板本地值 / 处理结果**，主数据原样不动。
  人工二选一裁决：`保留工坊值`（拒收该回执）或 `采用本地值`（强制并入并重算）。
- **同号回执只收一次**：相同回执 `id` 全局幂等，重复送达只在原回执上累计“重发×N”，绝不二次处理。
- **工序改动后级联重算**：先重算部件（工序状态、阴干、合拢、缺陷），再重算交付批次。
- **退回条件**：部件存在 **未闭缺陷 / 阴干未到 / 合拢未完成** 任一阻碍时，从所在交付批次摘出，
  原交付批次整批 `returned`（批内其余部件一并进入“待重排”，不悄悄换批）；
  阻碍解除后点 **重排待交付部件** 才重新成批。
- **失败重试与断点**：处理失败的回执保留错误原因，可 `重试`；
  缺工序/缺部件导致的失败可先 `补登缺失并重试`。每次状态变更整块落盘，
  刷新/重启自动从断点 `checkpoint` 继续，已终态回执不会重复处理。
- **导出**：导出包含冲突、当前状态汇总、工序、部件、缺陷、交付批次、全部回执与处理日志。

## 分层结构（存储 / 判定 / 页面分开）

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 存储 | `js/storage.js` | 仅负责整块状态在 localStorage 的读写与内存兜底，不含规则 |
| 判定 | `js/domain.js` | 纯函数式合并/冲突/幂等/重算/退回/重试/续跑规则，不依赖 DOM，可独立测试 |
| 页面 | `js/works.js` | 作品看板渲染与交互 |
| 页面 | `js/app.js` | 合并台编排：读输入 → 调 Domain → 存 Storage → 渲染 |

判定层对状态一律“草稿副本上计算，成功后整体提交”，任何一步失败都不会留下半成品数据。

## 回执包格式

```json
{
  "packageId": "PKG-20260929-01",
  "receipts": [
    {
      "id": "R-001",
      "batchNo": "WF2601",
      "opNo": "OP10",
      "seq": 3,
      "payload": {
        "opStatus": "待阴干",
        "parts": [{ "partId": "C02", "opStatus": "待阴干", "dryUntil": "2026-09-28",
                    "assemblyClosed": true, "planDelivery": "2026-10-02" }],
        "defects": [{ "defectId": "D1", "partId": "C02", "desc": "花瓣翘线", "closed": false }]
      }
    }
  ]
}
```

页面上点 **生成样例断网包** 可得到覆盖正常合并、序号乱到、缺工序失败、同号重发的示例。

```bash
node tests/domain.test.js   # 判定层规则：14 个断言块
node tests/smoke.js         # Storage + Domain 编排冒烟
node tests/dom-harness.js   # 最小 DOM 桩下真实执行 app.js 的完整交互路径
```
